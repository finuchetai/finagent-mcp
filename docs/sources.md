# Подключение отчётов клиента

Версия 0.3.0 читает подготовленные экспорты CSV, XLSX и PostgreSQL. Произвольная книга
Excel или схема БД сначала требует карты соответствия и при необходимости отдельного
преобразования. Адаптеры не строят ОПиУ из выписки и не выбирают учётную методику за клиента.

## Запуск из отдельной копии комплекта

```sh
python3 preflight.py environment
python3 -m venv .venv
.venv/bin/python -m pip install '.[files,postgres]'
.venv/bin/python -m finance_mcp.server --config examples/lipa/csv.json --check
.venv/bin/python examples/make_xlsx.py
.venv/bin/python -m finance_mcp.server --config examples/lipa/xlsx.json --check
```

Оба примера показывают `periods=4`, `reports=7`, `rows=40`. `--check` проверяет структуру
и согласованность экспорта. Правильность сумм подтверждается отдельной сверкой с
исходным отчётом. Независимый эталон примера — в `tests/test_sources.py`.

В stdio-клиенте укажите абсолютный путь к Python venv и аргументы
`["-m", "finance_mcp.server", "--config", "/absolute/path/client/config.json"]`.
Относительные пути JSON считаются от каталога JSON. Без config запускается демо «Маяк».

## Формат экспорта v1

JSON: `version: 1`, `adapter: "csv" | "xlsx" | "postgres"`, `client_id`, путь к UTF-8
Markdown `passport` и четыре объекта в `tables`. `max_rows` ограничивает каждую таблицу:
по умолчанию 100000, максимум 1000000. Паспорт согласуется с клиентом: метод начисления,
НДС/налоги/себестоимость, валюты, состав итогов, ограничения и свежесть данных.

| Таблица | Обязательные поля |
|---|---|
| periods | client_id, month, closed |
| reports | client_id, month, kind, currency, source, as_of, complete |
| rows | client_id, month, kind, code, label, dimension, amount, status |
| notes | client_id, month, note |

`month` — текст YYYY-MM; `kind` — pnl/cashflow/balances. `closed`, `complete` — строки
true/false в CSV, строки или логические ячейки XLSX, boolean в PostgreSQL. `as_of` — ISO
datetime с подтверждённым часовым поясом или timestamptz; при неизвестной дате — null
с as_of_status=unknown и отдельным received_at. Валюта — три заглавные буквы, конвертации
нет. Расходы передаются со знаком минус; итоги нельзя складывать с составляющими.

`status=value` требует конечную сумму. `missing` и `not_applicable` требуют пустую сумму
(NULL в БД); денежный ноль отличается от обоих. Пропуск требует `complete=false`.
Периоды и (month, kind) реестра уникальны; строки уникальны по
(month, kind, code, dimension). Реестр отчёта требует непустого набора строк.
Примечание на месяц не больше одного; без него ответ «Примечаний нет».
Потерянные связи между таблицами отклоняются до публикации снимка.

Период без ОПиУ допустим, фиктивную нулевую прибыль не создавайте. Открытые периоды
видны в списке, но их отчётность недоступна. Многопериодный запрос проходит целиком
или возвращает ошибку.

## CSV и XLSX

Новые необязательные поля reports: received_at, as_of_status, source_time_raw; rows:
source_id (нужен согласованный article_registry). Они включаются явной картой columns.
[Правила дат и постоянных кодов, совместимость и примеры](readiness.md).

Объект каждой таблицы содержит `file`, для XLSX также `sheet`. Заголовок — первая строка.
По умолчанию названия колонок равны полям формата; `columns` задаёт полную карту
«поле формата → имя колонки клиента». Порядок произвольный, дополнительные именованные
колонки не публикуются. Примеры с русскими заголовками — в examples/lipa.

CSV — UTF-8 с необязательным BOM; `delimiter` таблицы по умолчанию запятая.
`decimal_separator` всего экспорта — точка или запятая. Разделители тысяч, валютные
символы и экспоненциальная запись текстовых сумм требуют предварительного приведения.
Неизвестные статьи сохраняются, их нельзя отбрасывать ради нужного итога.

Числовая ячейка XLSX преобразуется в Decimal до вычислений. Формулы не исполняются:
читается сохранённое значение. Формула без результата и ячейка с ошибкой отклоняют
снимок. Перед экспортом пересчитайте и сохраните книгу в Excel/LibreOffice. Адаптер
не может установить, устарел ли кэш формулы: нужны дата среза и независимая сверка.

Файлы содержат только согласованного клиента. Чужой client_id, дубли, неверные заголовки,
суммы и статусы дают отказ. Источники открываются на чтение; повтор не добавляет строки.

## PostgreSQL

JSON задаёт `schema`, `dsn_env` (по умолчанию FINANCE_MCP_DSN); таблицы — `relation` и
при необходимости `columns`. Произвольный SQL в конфигурации/инструментах запрещён.
Имена — ASCII идентификаторы до 63 символов, экранируются через psycopg.sql.Identifier;
значения передаются параметрами.

Администратор клиента готовит четыре представления **только разрешённого клиента**,
отдельную LOGIN-роль без SUPERUSER/CREATEDB/CREATEROLE, даёт USAGE на схему экспорта
и SELECT на её представления. Исходные таблицы и другие клиенты роли недоступны.
Пример принципа (имена и условие определяет администратор, автоматически не выполнять):

```sql
CREATE VIEW finance_export.rows WITH (security_barrier=true) AS
SELECT client_id, month, kind, code, label, dimension, amount, status
FROM accounting.approved_report_rows WHERE client_id = 'client_b';
GRANT USAGE ON SCHEMA finance_export TO finance_reader;
GRANT SELECT ON finance_export.rows TO finance_reader;
```

Аналогично готовятся periods/reports/notes. Фильтр client_id в адаптере не заменяет
изоляцию роли/представлений. До MCP проверьте отказ роли на запись, прямое чтение
исходных таблиц и чтение другого клиента.

DSN передайте через локальное окружение процесса/хранилище секретов MCP-клиента,
не через чат, JSON или аргументы команды. JSON содержит лишь имя переменной.
Для удалённой БД настройте проверяемый TLS (`sslmode=verify-full`, доверенный сертификат).
Затем выполните `--config <postgres.json> --check` и подключите этот config к stdio-клиенту.

Чтение — одна REPEATABLE READ READ ONLY транзакция: connect_timeout 5 с,
statement_timeout 10 с, lock_timeout 2 с; каждый запрос ограничен max_rows+1.
Ошибки соединения/БД заменяются диагностикой без DSN и текста серверной ошибки.
Служебных записей в источник нет.

## Обновление и отключение

После старта сервер хранит проверенный снимок в памяти. Завершите экспорт, выполните
--check и перезапустите MCP для обновления. Файловый экспорт меняйте атомарной заменой
**всего каталога**; не редактируйте отдельные CSV/листы во время чтения. PostgreSQL
защищён общей транзакцией. Дата среза поступает из источника и должна быть верной.

Для отзыва доступа остановите MCP, удалите подключение/секреты, отзовите роль/файлы.
Отзыв роли сам по себе не удаляет снимок из памяти работающего сервера. Удалённый
HTTP/OAuth и автоматическое обновление остаются следующими этапами.

## Полная репетиция

После установки extras сначала выполните [preflight и stdio-пробу](readiness.md), затем
`python -m unittest discover -s tests -v`. PG-suite сам проверяет prerequisites до initdb.
Для PostgreSQL задайте FINANCE_MCP_TEST_PG_BINDIR — каталог серверных программ
initdb/pg_ctl/postgres (например /usr/lib/postgresql/18/bin). При нестандартном размещении
FINANCE_MCP_TEST_PG_SHAREDIR задаёт каталог системных файлов. Запуск обычным пользователем,
не root, на Linux/WSL. Тесты создают/останавливают собственный временный кластер, только Unix-сокет;
существующие БД не используются. Без переменной PostgreSQL-тесты явно пропускаются,
и такой прогон не подтверждает PostgreSQL-адаптер.

Результат фиксируется в [акте сверки](acceptance-template.md); успешные тесты не
подменяют подтверждение методики/полноты и построчное сравнение данных клиента.

«Липа» — искусственный клиент: 40 строк, 7 отчётов, две точки, четыре периода.
Сверяются все поля/метаданные, денежные тождества, права роли, ошибки, сохранность
источников и настоящие вызовы шести MCP-инструментов для каждого формата. Реальное
внедрение требует отдельного согласованного паспорта и сверки.

Документация библиотек: [openpyxl](https://openpyxl.readthedocs.io/en/3.1/api/openpyxl.reader.excel.html),
[psycopg](https://www.psycopg.org/psycopg3/docs/basic/transactions.html).
