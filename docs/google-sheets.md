# Google Sheets: вход через Google и актуальные данные

Основной клиентский сценарий с 0.6.0: вход в Google в браузере → ссылка на таблицу →
сверка карты агентом → MCP перечитывает таблицу → ассистент строит анализ или дашборд.
Клиент не создаёт Cloud project, service account и JSON-ключ. Оригинал можно читать
с разрешения владельца. Подключение Google Drive у ассистента не заменяет авторизацию MCP.

## Сценарий для владельца

Агент объясняет: «Подключим вашу таблицу. Откроется Google — выберите аккаунт и
разрешите чтение, затем пришлите ссылку на нужную таблицу. Я проверю её структуру
и сверю данные». Дальше по одному шагу; готовность месяца и методику уточнять отдельно.

Google показывает разрешение на чтение ВСЕХ доступных этому пользователю Google-таблиц.
Google не предлагает здесь сочетание «одна выбранная книга + только чтение». Приложение
ограничивает запросы ID согласованной книги и заданными диапазонами, но не скрывает
широту OAuth-разрешения. Отдельное Google-приложение каждого клиента для этого не нужно.
Если владелец не согласен с областью доступа, предложить файл или дополнительный вариант
с отдельным service account Viewer, не подменять scope на дающий запись drive.file.

## Шаги агента на компьютере владельца

1. Установить пакет в отдельную venv с extra sheets. Использовать тот же профиль ОС,
   в котором будет работать MCP. Не запускать login внутри MCP stdio или финансового tool call.
2. Запустить `finance-mcp-google login --profile owner` (или `python -m finance_mcp.google_oauth login --profile owner`).
   Клиенту не нужно печатать эту команду, если агент может выполнить её сам.
   Открывается системный браузер с Google; обратный адрес — случайный порт 127.0.0.1,
   защита PKCE и проверка state. Время ожидания 180 секунд. Нет копирования кодов в чат.
3. Разрешение и refresh token сохраняются в защищённом хранилище ОС (Windows Credential
   Manager, macOS Keychain, Linux Secret Service/KWallet). Токены не выводятся, не
   сохраняются в открытый JSON и не входят в исходный ZIP. Если хранилище недоступно,
   агент помогает настроить его; нельзя молча использовать plaintext-файл. В WSL и
   Windows разные профили/хранилища: login и MCP должны использовать одно окружение.
4. Агент получает ссылку на книгу и готовит config.json: adapter=google_sheets,
   spreadsheet_id=ID выбранной книги, oauth_profile=owner. credentials_env убрать —
   это дополнительный service-account режим. Подготовить паспорт, периоды и карту
   по правилам ниже. Сначала --check и полная сверка; потом реальные вызовы в клиенте.
5. `finance-mcp-google status --profile owner` подтверждает только наличие сохранённого
   разрешения. Успех MCP доказывают get_passport, list_months, refresh_source и отчёт.
   Истёкшее разрешение обновляется библиотекой автоматически. При отзыве/ошибке
   предложить повторный вход, а не запрашивать пароль или текст токена.

Это локальный OAuth Desktop flow. Для удалённого MCP подключение ChatGPT по HTTPS
сохраняется, но Google-login и хранилище разрешения должны находиться в окружении
самого MCP. Loopback login на сервере нельзя выдавать за готовый web callback:
полноценная серверная Google OAuth web-авторизация в этой версии не реализована.
Не переносить пользовательские токены в чат или на сервер автора ради обхода ограничения.
Два разных OAuth-соединения: клиент → MCP и MCP → Google.

## Разовая подготовка автором продукта

До реального клиентского входа автор регистрирует Google OAuth Desktop app, включает
Sheets API, настраивает экран согласия и тестовых пользователей/проверку Google для
публичного распространения. См. [инструкцию автору](google-app-registration.md).
Зарегистрированная Desktop-конфигурация не включена в этот репозиторий. Владелец
проверил настоящий вход и чтение в своей Windows-среде с отдельно настроенным приложением;
это не доказывает готовность новой установки у другого пользователя. Не просить каждого клиента
создавать своё приложение и не заменять отсутствующий ID вымышленным.

Конфигурация приложения предоставляется автором через FINANCE_GOOGLE_OAUTH_APP или
ресурс resources/google-oauth-client.json. Это OAuth Desktop client приложения, не
ключ сервисного аккаунта пользователя. Агент-разработчик может передать --app на login.
После входа runtime использует сохранённое разрешение; отдельный файл приложения в
клиентском config.json не требуется. Desktop client является public client, его
client_secret не считается надёжным серверным секретом. Web client secrets сюда не подходят.

## Карта данных

JSON version=1, adapter=google_sheets, client_id, passport, spreadsheet_id,
oauth_profile и четыре таблицы periods/reports/rows/notes. Метаданные можно хранить
в локальных CSV (`file`), данные — в выбранном `range`. Нормализованный диапазон
содержит заголовки полей с картой columns. При использовании as_of_status, received_at,
source_time_raw включить их в columns. Для неизвестной даты учёта — as_of пустым и
as_of_status=unknown. received_at ставится по времени чтения и не подменяет as_of.

Пример широкого отчёта (месяцы в колонках), tables.rows:

```json
{
  "range": "'ДДС'!A1:I100",
  "wide": {
    "kind": "cashflow",
    "header_row": 1,
    "label_column": 0,
    "months": {"2026-09": {"column": 6, "header": "2026-09"}},
    "entries": [
      {"row": 3, "label": "Поступления", "code": "receipts", "dimension": "detail"},
      {"row": 20, "label": "Денежный поток", "code": "net_cashflow", "dimension": "published_total"}
    ]
  }
}
```

Индексы начинаются с нуля внутри диапазона. Header — точное исходное значение:
даты Google возвращаются числовыми serial number, не строкой отображения. Названия
строк и заголовки проверяются при каждом обновлении. Изменение структуры требует
пересверки карты. Стабильные коды назначаются и сохраняются агентом, не вычисляются
заново из названия/позиции. Итоги, контроль и детали не складывать вместе.
Wide читает один прямоугольник одного вида отчёта за настроенные месяцы. План и
отклонения нельзя выдавать за факт: отдельного типа планового отчёта пока нет.
Полный ОПиУ из денежных поступлений не строится. Частичные данные — complete=false.

## Обновление

Перед каждым get_pnl/get_cashflow/get_balances сервер автоматически перечитывает
Google Sheets, валидирует и атомарно заменяет снимок. Ошибка обновления блокирует
этот ответ: старые суммы не возвращаются как свежие. refresh_source доступен также
для отдельной проверки обновления. Фонового опроса нет; текущий набор месяцев и
карта согласуются отдельно. Новые месяцы не становятся closed автоматически.

Два последовательных чтения должны совпасть, но это не транзакционная гарантия Google.
Для строгой сверки попросить не редактировать диапазон во время проверки. Ответ до
16 MiB; сетевой таймаут 30 секунд на запрос. Диапазон должен иметь свободную строку
в конце — иначе возможное обрезание вызывает отказ. Ошибки формул, пропуски, изменение
клиента и карты не замалчиваются. Суммы Decimal, без округления адаптером; погрешности
уже вычисленных Google формул возможны, допуск сверки согласуется отдельно.

Старый снимок после неудачного обновления остаётся в памяти, возраст виден в паспорте,
но get_* отчёты не выдают его без успешного обновления. Для отключения агент выполняет
`finance-mcp-google disconnect --profile owner`, проверяет подтверждение отзыва Google
и останавливает MCP, чтобы удалить активную сессию/снимок. Отзыв разрешения приложения
может затронуть другие его подключения того же Google-аккаунта. При ошибке отзыва не
объявлять отключение: предложить настройки Google-аккаунта и остановку процесса.

## Дополнительный вариант

Сервисный аккаунт поддержан по явному выбору администратора: credentials_env вместо
oauth_profile, отдельный аккаунт с ролью Viewer на выбранной книге, Sheets API и ключ
только в локальном защищённом окружении владельца. Не предлагать его по умолчанию.

## Проверки

Тесты используют синтетические ответы Google/хранилище/браузер, проверяют PKCE/state,
readonly scope, отказ входа/отзыва, безопасные ошибки, обновление и старый снимок.
Регистрация приложения, согласие и хранилище требуют отдельной live-приёмки каждой
поддерживаемой установки; Windows-сценарий владельца уже проверен. Чтение книги через Google Drive ассистента
не является этой проверкой.
