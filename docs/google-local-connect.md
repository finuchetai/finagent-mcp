# Локальное подключение Google Sheets к Codex — TASK-574

Предварительная версия 0.7.0rc2. Готовый Windows-комплект выдаётся отдельно
от исходников: в обычном клоне нет Start.cmd или настроек Google-приложения.
Комплект `finagent-google-codex-0.7.0rc2.zip` подготовлен как отдельное вложение
предварительного GitHub Release; до публикации черновика публичной загрузки нет.
Проверен сценарий чтения ДДС в Codex на Windows, включая внешний тест и новый
чат после перезапуска. Остатки не объявляются принятыми в пользовательском UI.

На 14.11.2026 Google Branding проверен и опубликован; приложение переведено
в Production, заявка на проверку доступа к таблицам находится на рассмотрении.
Production не означает одобрения sensitive scope. Массовый Google-вход пока
не объявляется проверенным или одобренным Google.

## Путь нового пользователя

1. Установленные Codex и Python3.11+; ZIP полностью распакован.
2. Start.cmd создаёт отдельную venv в ~/.finagent/runtime/<версия>-<хэш>.
   Исходники перед pip копируются во временную сборку; проверенный комплект не меняется.
3. Вход Google, ссылка на разрешённую книгу, выбор отчёта/месяца, валюта, подтверждение денежных единиц и
   готовности месяца. Карта JSON, паспорт и метаданные создаются автоматически.
4. Настоящий stdio запускает get_passport, list_months и финансовый инструмент.
   Если чтение не подтверждено, регистрация Codex не выполняется.
5. Codex CLI сохраняет новый сервер finagent-<профиль>. Прежние подключения остаются.
   Перед записью сохраняется точная приватная резервная копия config.toml.
   Только у нового сервера startup_timeout_sec=90 для Google-чтения при запуске.
6. Пользователь перезапускает Codex и в новом чате просит прочитать паспорт/месяцы и
   разобрать отчёт. Сохранение записи и SDK не являются проверкой интерфейса.

Start.cmd предназначен для Windows. Для агента доступны:
python -m finance_mcp.local_setup --profile google
python -m finance_mcp.google_connect --profile google
Второй вариант готовит источник без регистрации клиента. --json даёт машинный результат.
--url позволяет агенту передать уже согласованную ссылку. Новое имя профиля сохраняет
старую тестовую среду отдельно. Повторный запуск использует сохранённый профиль;
другая книга и чужая/отключённая запись Codex не перезаписываются.
Незавершённая собственная регистрация восстанавливает таймаут при повторе.

## Упаковка автором

python -m finance_mcp.local_bundle --app <Desktop-app.json> --output <новая-папка>

В комплекте заранее настроенное Desktop public client приложение автора.
Grant/keyring, финансовая книга и индивидуальный config.json автора не копируются.
В исходном Git google-oauth-client.json остаётся исключённым; он добавляется при сборке.
В настройки Codex не помещаются Google-токены. Пользовательский grant остаётся в
системном keyring того же пользователя Windows.
Manifest проверяет состав/контрольные суммы исходников перед установкой.
Это проверка целостности, не цифровая подпись распространителя.

## Поддержанные существующие отчёты
Одна согласованная существующая книга, выбранный отчёт и месяц. Таблицу менять не нужно.
Ссылка уже дана — использовать её, не просить другую тестовую книгу или копию.
Автоматически читаются:
- ДДС/ОПиУ: Статья/Показатель в колонке A, месяцы с годом в строке заголовков.
- Остатки: Счёт в A, Показатель в B, месяцы с годом или числовые даты Google далее.
  Две подписи сохраняются и проверяются отдельно, одинаковые счета не сливаются.
- Итого/Всего/Total по разным месяцам и именованные примечания — дополнительные колонки;
  они явно исключаются из выбранного месячного отчёта. Пустая служебная колонка допустима.
- Заголовки деятельности ДДС и блок Примечания отделяются от денежных строк.
  Их состав сохраняется в карте; изменение требует повторной проверки.
Даты: YYYY-MM, YYYY-MM-01, MM.YYYY, 01.MM.YYYY, «октябрь 2026», «October 2026»,
либо числовая дата Google на первое число при явных заголовках отчёта.
Все значения месяца сохраняются со знаками, нулями и пропусками. Итоги и детали
не суммируются. Название «Кредиты и займы (%)» допустимо как денежные проценты
по займам только вместе с подтверждением денежных единиц; процентные метрики
и количества по-прежнему не принимаются как деньги.
Списки операций Журнал/Регулярные и планы не подменяют готовый месячный отчёт.
При неизвестной колонке или нескольких месячных таблицах сохранить точную диагностику
для агента и проверки карты этой книги. Не требовать от владельца другую книгу,
переделку отчёта, копию или редактирование суммы.
Подключение проверяется повторными настоящими вызовами MCP, без изменения источника.

До30 листов, до100 колонок, до5000 строк; последняя строка диапазона свободна.
План/прогноз, план/факт рядом, повторные месяцы/названия, дополнительные колонки,
несколько таблиц на листе и журнал операций автоматически не подключаются.
Большие листы отклоняются по полному размеру grid, даже если возвращённый фрагмент короткий.
Размер/идентичность листа проверяются до и после чтения; пояснения единиц сохраняются в карте.
Изменение границ листа, состава/положения/названия строк, пояснений или заголовков требует
пересверки карты. Ошибка обновления блокирует новый финансовый ответ.
Коды остаются в сохранённой карте и не пересчитываются по переименованным строкам.

complete=false, as_of unknown. Подтверждение готовности месяца не подтверждает
полноту или методику. Все строки выдаются отдельно: итоги и детали не складываются.
Первый разбор показывает значения и пропуски; прибыль из ДДС не выводится.
Полный анализ выполняет агент по реальным MCP-ответам в обозначенных границах.

## Что принято техническими проверками

Автотесты проходят через настоящий discovery→сохранение→load_adapter→адаптер→
FinanceService→MCPServer; подменён HTTP Google. Проверки Codex используют подмену CLI,
но реально читают/пишут/повторно читают TOML и резервную копию.
Настоящий stdio отдельно читает непустой эталонный финансовый отчёт.
Windows bootstrap check2: Python3.12, установка0.7.0rc1 в новую venv успешна;
в пакете найдена Desktop app, реальный stdio с прежним разрешением автора:
7tools, ДДС2026-09/USD/30строк. Суммы и токены в акт не включены.
Это проверка компьютера автора, не нового пользователя.

Для выдаваемого комплекта нужны окончательный сборочный manifest и проверка
его состава. В режиме Google Testing аккаунт тестировщика должен быть добавлен
автором. Завершённая внешняя приёмка ограничена ДДС в Codex на Windows;
она не подтверждает все форматы таблиц, другие клиенты или отчёт по остаткам.
Изменение ячейки не требуется для подключения.
Одобрение доступа Google и серверный Google Web OAuth — отдельные этапы.

Распакуйте новый комплект отдельно, прежний не удаляйте. Запустите Start.cmd с тем же
--profile google и уже предоставленным --url. Если прошлый запуск остановился до

существующего законченного профиля сначала покажите его путь/состояние агенту.
