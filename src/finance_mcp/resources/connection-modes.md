# Один финансовый MCP, несколько клиентов

## Что значит универсальность

Те же шесть инструментов и тот же согласованный снимок доступны через stdio или
Streamable HTTP. Клиент выбирает приложение, агент — совместимый способ подключения.
Не обещается поддержка каждого тарифа/версии ChatGPT. Данные остаются на компьютере
или сервере владельца; сервер разработчика для этого не требуется.

| Приложение | Способ | Требования |
|---|---|---|
| ChatGPT в браузере | Удалённый MCP/плагин по HTTPS | Сервер клиента, OAuth-провайдер, права подключения в ChatGPT |
| Настольный ChatGPT | Тот же HTTPS MCP; локальный плагин, если доступен | Реально поддерживаемый тип установки; для local — Python/venv на компьютере |
| Другой stdio-клиент, включая Codex | Локальный процесс или local plugin | stdio и/или поддержка portable plugin package |
| Другой HTTP MCP-клиент | Тот же HTTPS MCP | OAuth 2.1/PKCE и совместимые настройки провайдера |

Переключение транспорта не переносит данные автоматически и не меняет финансовую методику.
Одному клиентскому снимку соответствует один процесс/endpoint. Каждый разрешённый OAuth
пользователь этого endpoint видит весь данный снимок: это НЕ многоклиентский хостинг.
Не объединяйте разных клиентов в одном процессе/списке субъектов.

## Локальное подключение

Обычные команды версии 0.3.0 остаются действительными: без --transport запускается stdio.
Агент создаёт venv, устанавливает пакет, выполняет диагностику и сверку, затем генерирует
плагин на компьютере владельца (не копирует абсолютные пути разработчика):

```sh
.venv/bin/python -m finance_mcp.plugin_package local   --python /absolute/path/to/.venv/bin/python   --config /absolute/path/to/export/config.json --output /absolute/path/to/finagent-finance-local
```

Без --config используется искусственное демо. На Windows указать Python из Scripts.
Каталог содержит plugin.json, mcp.json, launch.py и skill пошаговой настройки. Данные и
venv в пакет не копируются, существующая конфигурация остаётся у владельца.
Устанавливайте через поддерживаемый данным клиентом локальный механизм плагинов.
Если он не поддерживается — обычная регистрация stdio; если и она отсутствует — HTTPS.
Генератор не устанавливает плагин автоматически и не открывает доступ к файлам.

Секретов в пакете нет, но при --config там указан локальный путь владельца.
Не раздавайте этот индивидуально собранный пакет другим пользователям вместо генерации
под их окружение. Для публичного распространения предназначены исходники и инструкции.

## Удалённый сервер для браузера

В этой версии реализована сторона **OAuth resource server**: проверка access token,
подписи RS256, issuer, audience, срока, scope finance:read и разрешённых sub владельцев.
Сам сервер не выдаёт токены и не содержит страницы входа/паролей. Для самостоятельного
развёртывания нужен настроенный внешний OAuth/OIDC-провайдер с совместимым клиентским
подключением (в том числе PKCE и точными callback URL, которые покажет целевой клиент).

Агент сначала выясняет инфраструктуру владельца; не просит нетехнического пользователя
самостоятельно подбирать issuer/JWKS или придумывать коды доступа. Настройка провайдера
и фактический браузерный вход — обязательная отдельная проверка, не результат сборки ZIP.
Если провайдера/сервера нет, нельзя объявить браузерное подключение готовым.

Установить пакет с extras remote и нужными адаптерами. В окружении серверного процесса:

- FINANCE_MCP_PUBLIC_URL: фактический HTTPS endpoint с путём /mcp, без query/fragment/ключей.
- FINANCE_MCP_OAUTH_ISSUER: точный HTTPS issuer из реальных настроек провайдера.
- FINANCE_MCP_JWKS_URL: его подтверждённый HTTPS JWKS URL, не адрес из клиентского токена.
- FINANCE_MCP_ALLOWED_SUBJECTS: непустой JSON-массив sub разрешённых владельцев снимка.

Выдаваемый **access token** должен иметь aud равный PUBLIC_URL, exp/iat/iss/sub,
scope с finance:read и client_id либо azp. ID token вместо access token не использовать.
Все настройки берутся из реального провайдера, не из примера этого документа.

```sh
.venv/bin/python -m finance_mcp.server --config /absolute/export/config.json   --transport streamable-http --host 127.0.0.1 --port 8000
```

Без обязательных параметров удалённый режим отказывается запускаться. Анонимного HTTP
режима нет. Reverse proxy владельца завершает HTTPS и сохраняет Authorization и Host
публичного домена. DNS-rebinding protection включена. Настройки разрешённых sub не
заменяют разграничение файлов/ролей исходника. Обновление/отзыв доступа как в sources.md.

В deploy/ приведены Dockerfile, loopback-only compose и фрагмент Caddy. Перед применением
проверить существующие порты/прокси/права и использовать отдельный клиентский экспорт.
Секреты вводить локально, не отправлять в чат, Git или manifest. Создание/покупка сервера,
домен и настройка существующей инфраструктуры выполняются только в разрешённом объёме.

Проверить до подключения:

1. Без токена /mcp возвращает 401 и ссылку на protected resource metadata.
2. Метаданные доступны по /.well-known/oauth-protected-resource/mcp, содержат фактический issuer.
3. Неверные подпись/issuer/aud/sub/scope и истёкший токен не открывают инструменты.
4. Через настоящий OAuth access token работают initialize и шесть финансовых инструментов.
5. Вход и чтение именно в выбранном интерфейсе пользователя подтверждены фактическими вызовами.

## Удалённый plugin package

После проверки endpoint и настройки зарегистрированного OAuth-клиента:

```sh
.venv/bin/python -m finance_mcp.plugin_package remote   --endpoint https://YOUR-VERIFIED-HOST/mcp --oauth-client-id YOUR-REGISTERED-CLIENT-ID   --output /absolute/path/to/finagent-finance-remote
```

Команда содержит обозначения для замены, не действующий endpoint. Генератор проверяет
структуру, но не доказывает сетевую доступность URL или регистрацию ID. Сначала агент
проверяет реальный endpoint/OAuth по предыдущему разделу; фиктивные адреса не подключать.
Генератор описывает public OAuth client с tokenEndpointAuthMethod=none; если провайдер/
целевой клиент требует confidential client или иной режим регистрации, сперва согласовать
настройку и поддерживаемый поток, не вкладывать client secret в пакет.

Для браузерного ChatGPT используйте поддерживаемый поток Add custom MCP server/Create
as a plugin либо соответствующий установленный приватный плагин. Наличие поля OAuth в
manifest не заменяет реальную регистрацию/вход. Не подменяйте OAuth статическим ключом.
Пакет не содержит OAuth-токенов, парольной базы и клиентских финансовых файлов.

## Граница распространения

Локальная/приватная установка и публичный каталог — разные этапы. Публикация локальных
MCP-плагинов в каталоге OpenAI доступна ограниченному кругу одобренных партнёров;
не обещать установку local stdio из публичного каталога любому пользователю.
Репозиторий пока приватный, публичная подача не выполняется. Для HTTP-плагина нужны
проверенный HTTPS endpoint и работающая авторизация; текущие локальные тесты не равны
готовому ChatGPT-подключению. PyPI, OAuth-хостинг и сервер клиента сами не создаются.
