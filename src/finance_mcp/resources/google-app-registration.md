# Одна настройка Google-приложения автором Финагента

Пришлите ссылку на Google-таблицу с финансовыми данными, которую хотите подключить. MCP будет только читать данные, ничего в таблице не изменяя.
Не требовать отдельную тестовую книгу, создание копии или изменение ячеек.
При ошибке карты разбирать исходную книгу; не предлагать заменить её ради теста.

Это инструкция автору продукта, не каждому клиенту. До выполнения нельзя обещать
работающую кнопку Google или автоматически созданное приложение. В 0.6.0 вход
запускает агент через CLI; отдельный графический установщик ещё не сделан.

1. В Google Cloud Console под аккаунтом владельца продукта создать/выбрать проект,
   включить Google Sheets API.
2. В Google Auth Platform настроить название Финагент, контакты поддержки,
   аудиторию External и действующие страницы продукта/политики конфиденциальности.
   Домены и публичные данные заполнять проверенными значениями, не вымышленными ссылками.
3. Запросить только spreadsheets.readonly. Оно sensitive и даёт чтение всех доступных
   пользователю таблиц; выбранную книгу ограничивает дополнительно сам MCP.
   Не добавлять drive/drive.file или scope записи ради упрощения проверки.
4. Для первого теста указать согласованный Google-аккаунт тестировщика в Test users.
   Настроить OAuth client типа Desktop app. Полученную конфигурацию installed сохранить
   локально у разработчика, не пересылать сервисные ключи клиента. Передать агенту
   путь через FINANCE_GOOGLE_OAUTH_APP либо --app. Пакет с зарегистрированной Desktop
   конфигурацией затем собирает автор. Серверный Web client secret сюда не включать.
5. Запустить login на компьютере тестировщика, проверить scope на экране Google,
   чтение выбранной книги, реальный refresh_source/get_cashflow и повторный запуск MCP.
   Разрешение хранится в системном keyring того же профиля ОС. Для подключения не нужны
   отдельная тестовая книга, копия или изменение значений; проверять только чтением.
6. До массового распространения пройти требуемую Google проверку sensitive scope
   и перевести проект в подходящий режим публикации. В режиме Testing действуют
   ограничения тестовых пользователей и срока разрешений; не называть его готовым
   постоянным подключением. Не просить пользователей обходить предупреждения Google.

Нужны реальные OAuth Desktop client настройки от владельца Google-проекта. Ни
Google Drive-коннектор ассистента, ни GitHub, ни MCP-манифест их не создают.

Для полноценного web-входа на удалённом сервере нужен отдельный OAuth Web client,
HTTPS callback, защищённое серверное хранилище и проверка связи пользователя с MCP.
Текущий loopback Desktop flow не заменяет эту работу. Настройки Google авторизации
не подменяют OAuth для подключения самого MCP к ChatGPT.

Источники: https://developers.google.com/identity/protocols/oauth2/native-app,
https://developers.google.com/workspace/guides/configure-oauth-consent,
https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification.
